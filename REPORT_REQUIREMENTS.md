Reference: `Queueing_Calculator_Report_Final.pdf`, supplied by the user, pages 3–8. The PDF is a specification/reference; it is not bundled into the application.

Layout remains code-built rather than introducing a generated Designer file into the existing hand-built WinForms project. The calculator allows up to 100,000 servers as a practical input bound; the separate timed simulator retains its 100-server resource limit.

## Units and variance

All calculator calculations use minutes internally. For a unit containing `f` minutes:

- Rate input: `lambda = value / f` (same for mu).
- Mean time input: `lambda = 1 / (value * f)`.
- Variance input: `variance_minutes = variance * f^2`.
- Standard deviation: square after converting the deviation into minutes.
- Uniform bounds: convert the resulting variance into minutes squared.

Uniform bounds provide variance only, as described in the report; arrival/service means remain separate inputs. Changing a unit selector changes the interpretation of the entered number; it does not rewrite the number.

## Formula reference

`rho = lambda / (S*mu)`, `Ca² = Var(A)*lambda²`, `Cs² = Var(S)*mu²`.

- M/M/1 and M/M/S use Erlang C with a log-space normalizer for P0 and stable Erlang B recursion for the wait probability.
- M/G/1 uses Pollaczek–Khinchine: `Wq = rho*(1+Cs²)/(2*mu*(1-rho))`.
- G/G/1 uses Marchal: `Lq ≈ rho²*(1+Cs²)*(Ca²+rho²*Cs²)/(2*(1-rho)*(1+rho²*Cs²))`.
- M/G/2 uses the report's approximation: `Wq ≈ Wq(M/M/2)*(1+Cs²)/2`.
- In each case: `W = Wq + 1/mu`, `Lq = lambda*Wq`, `L = lambda*W`.

Marchal formula cross-check: [research paper, equation 2](https://pmc.ncbi.nlm.nih.gov/articles/PMC9086425/). Original reference: [Marchal, An Approximate Formula for Waiting Time in Single Server Queues (1976)](https://www.tandfonline.com/doi/abs/10.1080/05695557608975111).

G/G/1 and M/G/2 waiting and queue measures are approximations, not exact predictions. For any work-conserving stable single-server queue, the time-stationary empty fraction is `1-rho`. For multiple servers, average idle capacity `1-rho` is not the all-empty probability. M/G/2 P0 cannot be determined exactly from the first two moments alone; it is explicitly unavailable rather than borrowed from M/M/2.

## Sample data limitations

The report references `Queueing_Models_Data.xlsx`, but that workbook was not supplied. The report itself gives only scenario names, arrival/service rates, models and stability. Presets reproduce those values and deliberately leave missing general-model variances blank. The peak bank example is intentionally unstable. No unprovided variances or workbook outputs have been invented.

## Build and validation

Run `dotnet build Assignment.csproj`, then press F5 in Visual Studio or run `dotnet run --project Assignment.csproj`. Stop any running simulator before rebuilding, because Windows locks its executable.

Run `dotnet run --project Checks/Checks.csproj` for analytical, numerical, simulation and UI-event regression checks. Passing `-- --preview` additionally opens the form temporarily and saves layout previews under ignored `tmp/previews`.

Keep `bin` and `obj` locally for Visual Studio to launch the application. They are ignored build artifacts, and can be regenerated by a normal restore/build.
